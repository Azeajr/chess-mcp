# WP-008 — Keyboard command registry surface and shortcut help

## Objective and findings

**Objective.** Make shortcuts discoverable and their scope explicit.

**Audit findings addressed.** UX-044

## Dependencies and gates

**Dependencies.** WP-007, plus the `content-label-foundation` prerequisite (execution correction; see ../README.md and ../decisions/content-label-foundation.md). The full WP-024 migration is deliberately not a dependency.

**Blocking gates.** None.

**Blocks.** none

**Parallel with.** WP-013, WP-015, WP-018

## Current behavior

Shortcuts exist only in `App.tsx:45–65`. No help sheet, no tooltip listing keys, no customisation, no mention in Settings.

## Target behavior

`?` (and a Settings entry, and a top-bar overflow-menu entry) opens a dialog listing every registered shortcut grouped by scope, showing platform-correct key names (`⌘` vs `Ctrl`), and stating which are active only in a particular context. Customisation is explicitly out of scope and stated as such.

## Relevant files and symbols

- `App.tsx:45–65`
- `src/components/ShortcutHelpDialog.tsx`
- `store/shortcuts.ts`
- `content/index.ts`

## Implementation approach

New `src/components/ShortcutHelpDialog.tsx` rendering `activeShortcuts()` from `store/shortcuts.ts`, grouped by `scope`. The preceding `content-label-foundation` provides only the six shortcut labels and platform-key formatter; it is later absorbed by WP-024. Platform detection from `navigator.platform`/`userAgentData`. Register `app.help` (`?`, global scope, not in text fields).

## Behaviors to preserve

Registering the help shortcut must not shadow `?` typed into the chat textarea or any input.

## Acceptance criteria

- Pressing `?` with focus on the document body opens the shortcut dialog; pressing `?` inside the chat textarea types a question mark and does not open it.

- The dialog lists at minimum: save, undo, redo, previous move, next move, help — each with a human label and the platform-correct key.

- Shortcuts registered by a modal scope are not listed while no modal is open.

- The dialog satisfies the `Dialog` contract.

## Automated completion validation

**Automated tests.** Playwright: `?` behaviour in and out of a text field; list contents assertion; contract suite inclusion.

**Automated validation.** The package must satisfy its `requiredAutomatedValidation` contract in `manifest.json`; deterministic failure, missing evidence, or an inconclusive result blocks completion.

## Failure and rollback contract

**Planned risk.** Low

Low risk; revert removes the dialog and the `?` registration.
