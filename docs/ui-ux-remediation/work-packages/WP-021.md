# WP-021 — Chat rail until the assistant is configured

## Objective and findings

**Objective.** Stop reserving a quarter of the workspace for a feature that cannot run.

**Audit findings addressed.** UX-028

## Dependencies and gates

**Dependencies.** WP-000, WP-024

**Blocking gates.** None. PD-4 is fixed: keep the chat column at full width and replace its content with the setup card.

**Blocks.** none

**Parallel with.** WP-015, WP-016, WP-018

## Current behavior

`.chat-wrap` is always rendered at the persisted width (default 360 px). Verified at 1440×900: 360 px of full-height column containing only the panel head and `No API key. Open Settings`. `hasApiKey()` (`store/settings.ts`) is false until a key is entered.

## Target behavior

While `hasApiKey()` is false, the chat column keeps its persisted width and `ChatPanel` replaces the terse `No API key. Open Settings` line with a setup card: a heading, one sentence describing what the assistant does, and a `Set up the assistant` control that opens Settings focused on the API-key field. Once a key exists the card is replaced by the live chat surface, at the same width and without remounting adjacent panels. On mobile the Chat tab remains and its panel shows the same card.

**PD-4 decision.** Keep the column at full width and replace the terse error line with the setup card. Automation asserts the column and setup action remain present; comparative preference is not a completion claim.

**Acceptance criteria rewritten 2026-08-26.** AC-1 and AC-5 originally specified collapsing the column to a ≤ 56 px rail and disabling the divider while collapsed. PD-4 fixed the opposite approach, and §7 of the plan states that a gate returning a different answer does not reopen the finding — it changes the implementation, and the acceptance criteria are rewritten accordingly before the package starts. The rail text was that stale pre-gate wording; the criteria below are authoritative. `requiredAutomatedValidation` in `manifest.json` already described the full-width outcome and is unchanged.

## Relevant files and symbols

- `store/settings.ts`
- `App.tsx`
- `store/layout.ts`
- `ChatPanel.tsx`

## Implementation approach

`ChatPanel.tsx` renders a `ChatSetupCard` when `!hasApiKey()`, in place of the terse `No API key` line. The card's control reuses the `settingsFocusTarget` seam so Settings opens with focus on the API-key field. The chat column's width is untouched by configuration state — `App.tsx` and `store/layout.ts` keep sourcing it from the persisted value alone, which is what makes the persisted-width contract hold by construction rather than by restore logic.

## Behaviors to preserve

The persisted chat width must never be overwritten by the unconfigured state. The mobile Chat tab must remain present. The existing `No API key` link behaviour (opening Settings) must keep working.

## Acceptance criteria

- With no API key at 1440×900, `.chat-wrap` keeps its persisted width and its panel body renders the setup card in place of the terse `No API key` line.

- The setup card's control is keyboard reachable, has an accessible name, and opens Settings with focus on the API-key field.

- Adding a key leaves the chat column at its previously persisted width (assert the exact stored value) and swaps the setup card for the live chat surface.

- At 390×844 the Chat tab is present and shows the setup card.

- The side│chat divider stays focusable and draggable while the assistant is unconfigured, and the persisted width is never overwritten by the unconfigured state.

## Automated completion validation

**Automated tests.** Playwright: persisted width preserved while unconfigured, setup card present in place of the terse line, focus target on the API-key field, mobile tab presence.

**Automated validation.** The package must satisfy its `requiredAutomatedValidation` contract in `manifest.json`; deterministic failure, missing evidence, or an inconclusive result blocks completion.

## Failure and rollback contract

**Planned risk.** Low

Regression mode: the persisted width overwritten while unconfigured. Detection: the persisted-width assertion. Rollback: single revert.
