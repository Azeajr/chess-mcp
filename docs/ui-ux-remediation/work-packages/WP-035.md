# WP-035 — Strategic Fit Review/Redesign split: validation checkpoint

## Objective and findings

**Objective.** Decide, with evidence, whether the workspace should become two focused modes.

**Audit findings addressed.** Audit §4 (E2), §7, §13 Phase E — no numbered finding; the audit explicitly flags this as an XL product decision

## Dependencies and gates

**Dependencies.** WP-031, WP-032, WP-033

**Blocking gates.** None. PD-5 is fixed to no split unless a future separately authorized research initiative changes the product decision.

**Blocks.** any future split

**Parallel with.** WP-036–WP-038

## Current behavior

The audit recommends considering a split but is explicit that it is not an automatic implementation requirement, and that `WP-033`'s stage strip may already resolve the overload. Committing to an XL restructuring before that is measured would be exactly the "redesign to appear comprehensive" the audit warns against.

## Target behavior

No separate target-behavior section is stated in the source plan; the acceptance criterion below is the target contract for this validation-only package.

## Relevant files and symbols

- `docs/`

## Implementation approach

After `WP-033` ships, keep one workspace and run two automated journeys: a review journey ending in a decision and a redesign journey ending in an applied change set. The review journey must never enter redesign state without the explicit redesign action; the stage indicator must equal application state after every transition; the redesign journey must reach apply without duplicate resolution controls. Record the deterministic results and retain the no-split decision. Subjective clarity is not claimed.

- A machine-generated journey report records both transition traces, stage-state equality, explicit redesign-entry count, duplicate-control count, and pass/fail against the fixed thresholds. No production code changes and no split proposal are part of this package.
