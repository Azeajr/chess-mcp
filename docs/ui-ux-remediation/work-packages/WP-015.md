# WP-015 — Side-column reorder

## Objective and findings

**Objective.** Put the most-used panel where it can be seen without scrolling.

**Audit findings addressed.** UX-010

## Dependencies and gates

**Dependencies.** WP-000, WP-011

**Blocking gates.** None.

**Blocks.** none

**Parallel with.** WP-016, WP-018, WP-021

## Current behavior

`App.tsx:106–110` renders `.side-panel` children in the order `AnalysisPanel`, `RepertoirePanel`, `MoveTree`. Verified at 1440×900: the move tree starts at y ≈ 800 in a 900 px viewport, below ten collapsed repertoire sections and the Strategic Fit entry card. `styles.css:415–424` gives `.side-panel` `overflow-y: auto` and `.move-tree` `flex: 0 0 min(50vh, 28rem)` at ≥1101 px.

## Target behavior (as planned) and what actually shipped

The plan was: the move tree first in the column, visible without scrolling at every viewport ≥ 1024×600; Analysis follows; Repertoire tools last; and on mobile, `Moves` as the default tab.

Neither half shipped as planned. The mobile default was implemented, then deliberately reversed: `store/ui.ts`'s comment on `mobileTab` explains that the Repertoire panel — and with it the Strategic Fit entry point — lives inside the `Analysis` mobile tab, so defaulting to `Moves` hides the app's primary analysis affordance behind an extra tap on first run. `Analysis` remains the default. The desktop reorder was never carried out; no rationale for skipping it was recorded at the time.

Live measurement (2026-08-23, three matrix viewports) confirms the current, decided behavior: `.side-panel` still renders `AnalysisPanel`, `RepertoirePanel`, `MoveTree` in that order — the move tree's top edge sits ~1000–1200px down a 600–900px-tall viewport, with 0 rows visible without scrolling. The analysis panel's engine-lines area, by contrast, does stay within the viewport at all three widths — that half of the original spec (AC-2) was never at risk since it didn't depend on the reorder.

A brief comparison against lichess.org's and chess.com's analysis-board landing states (2026-08-23) found both surface engine/evaluation content ahead of other tools and the move list in reading order — closer to this app's current "Analysis first" behavior than to the original plan, though neither is a direct precedent for a populated move list.
